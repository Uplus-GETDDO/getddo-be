# 실행 근거 파일 보관

보고서의 실제 수치와 판정을 확인할 수 있는 근거를 보관합니다. 이 폴더에는 현재 보관 안내만 있으며 실행 결과 JSON·CSV를 생성한 것은 아닙니다.

## 자료별 보관 위치

| 자료 | 보관 위치 | 보고서에 연결할 내용 |
| --- | --- | --- |
| 결과 요약 Markdown | `reports/YYYY-MM-DD-주제.md` | 범위·조건·기대값·실제값·판정·한계 |
| 작은 정합성 대조 요약 JSON·CSV | 이 `assets/` 폴더에 필요한 파일만 커밋 | 검사 기준, 대상 수·불일치 수, 상세 자료 위치 |
| 필요한 소량의 불일치 상세 | 이 폴더 또는 별도 실행 아티팩트 | 테스트용 식별자·기대값·실제값·검사 기준 |
| 자동 생성 HTML·XML | 실행 아티팩트·첨부 보관 위치 | 원본 위치와 검증 범위 |
| 대용량 로그·부하 원본 | 별도 실행 아티팩트·첨부 보관 위치 | 필요한 구간과 요약 지표·해석 |

원본 파일 전체를 Git에 일괄 추가할 필요는 없습니다. 작은 파일이라도 본문에 적은 수치를 확인하는 데 필요한 자료를 선택합니다. 보관 위치의 접근 가능 여부·만료 여부를 확인하고 발표에 사용할 원본은 만료 전에 보존합니다. 현재 CI는 실패한 테스트 보고서만 7일 보관하므로 성공 결과·영구 보관을 자동으로 제공한다고 가정하지 않습니다.

## 이름과 상대 링크

- 같은 실행의 보고서와 근거 파일에 같은 날짜·주제를 사용합니다.
- 파일명 예: `YYYY-MM-DD-entry-concurrency-summary.csv`, `YYYY-MM-DD-entry-concurrency-mismatches.csv`.
- `reports/`에 있는 보고서는 `assets/파일명.csv`처럼 연결합니다.
- 실제로 존재하는 파일만 링크합니다. 위 파일명은 작성 예시이며 실제 결과 파일은 아닙니다.

## 요약 CSV 구성 예시

다음은 열 구성 예시이며 아직 생성된 실행 결과가 아닙니다. 수치와 판정은 실제 실행 후에만 작성합니다.

```csv
scenario_id,check_id,checked_count,mismatch_count,verdict,evidence
```

- `scenario_id`: 보고서의 시나리오 ID.
- `check_id`: 실제 검사한 불변식·대조 항목 식별자.
- `checked_count`, `mismatch_count`: 동일 기준 시점에서 실제 검사한 대상 수·불일치 수.
- `verdict`: 통과·실패·미실행·판정 불가. 검사 대상 0건을 통과로 처리하지 않습니다.
- `evidence`: 검사 쿼리·assertion 또는 상세 근거 파일 위치.

HTTP 요청 수·업무 처리 건수·검사 대상 수는 서로 다른 값일 수 있습니다. 단위와 집계 기준을 보고서에 적습니다. 검사 요약을 제공하는 것과 애플리케이션이 반환한 정합성 표시를 독립적으로 검증한 것은 구분합니다.

원본의 비밀값·개인정보를 포함하지 않습니다. 실행 조건을 확인할 수 없거나 여러 실행이 섞인 로컬 파일은 하나의 최신 검증 결과로 합산하지 않습니다.
