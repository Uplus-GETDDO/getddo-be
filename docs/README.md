# 작업과 결정 기록

작업한 날의 진행 상황과 고민을 사람별 일지에 기록합니다. AI로 초안을 작성할 때는 실제 대화·코드 변경·검증 결과를 근거로 삼고, 담당자가 확인합니다. 중요한 기술적 결정은 ADR로 남깁니다.

## 무엇을 기록하나요?

| 기록 | 작성 기준 | 파일명 예시 |
| --- | --- | --- |
| PR 설명 | 해당 변경의 목적·변경 내용·검증 결과 | PR 본문 |
| 작업 일지 | 작업한 날의 진행 상황·고민·확인 결과·다음 할 일 | `05-worklogs/성명/2026-09-22.md` |
| ADR | 여러 작업에 영향을 주거나 바꾸기 어려운 설계 결정 | `04-decisions/0001-decision-title.md` |

작업 일지는 `05-worklogs/성명/YYYY-MM-DD.md`에 작성합니다. 폴더명은 성을 포함한 이름으로 통일합니다. Jira 키와 PR은 일지 본문에서 링크로 연결합니다. ADR 번호는 기존 파일을 확인해 다음 번호를 사용합니다. 위 경로와 파일명은 예시입니다.

## 작성 순서

1. [일지 양식](templates/worklog.md)을 복사해 본인 폴더에 날짜별 파일을 만듭니다. 같은 날짜의 파일이 있으면 기존 내용에 이어서 작성합니다.
2. 오늘 한 일, 고민과 판단, 확인 결과·막힌 점, 다음 할 일을 짧게 정리합니다. 고민과 판단은 남길 내용이 있을 때만 작성합니다. 세부 규칙은 [작업 일지 안내](05-worklogs/README.md)를 따릅니다.
3. 관련 이슈·PR을 연결하고, 작업의 현재 상태는 해당 이슈에도 반영합니다. 백엔드 확정 설계는 해당 설계 문서에, 중요한 기술적 선택은 [ADR 양식](templates/adr.md)에 남긴 뒤 일지에서 연결합니다.
4. AI 초안에는 `담당자 확인 전`을 표시하고, 담당자가 선택 이유·실제 실행 결과·미확인 내용을 확인한 뒤 표시를 갱신합니다. ADR은 제안 상태로 시작합니다.
5. 코드 변경과 관련된 일지는 해당 PR에 함께 포함합니다. 일지만 작성한 경우에는 문서 PR로 공유할 수 있습니다. PR 설명에 넣는 일지 링크는 GitHub URL을 사용합니다.

실행하지 않은 테스트, 실제로 검토하지 않은 대안, 확인되지 않은 이유는 만들어 쓰지 않습니다. 검증 결과에는 실행한 명령과 실제 결과를 적고, 필요한 경우 기준 커밋·변경 범위·CI 링크를 덧붙입니다. 비밀번호·토큰·개인정보는 기록하지 않습니다. 테스트가 실패했다면 실패한 상태 그대로 기록합니다.

ADR을 대체할 때는 새 ADR을 작성하고 이전 ADR에 ‘대체됨’ 상태와 새 문서 링크를 남깁니다. 과거 기록은 당시 맥락이며, 다음 작업에서 현재 코드·정책과 달라졌는지 확인합니다.

## AI에게 요청할 문장

```text
오늘 작업을 docs/templates/worklog.md 양식으로 정리해줘.
내 성명은 [성명], 기록할 날짜는 [YYYY-MM-DD]야.
초안은 docs/05-worklogs/[성명]/[YYYY-MM-DD].md에 저장해줘.
같은 날짜의 파일이 있으면 기존 내용을 보존하고 오늘 추가한 작업을 반영해줘.
대화, 실제 diff, 테스트 실행 결과를 근거로
오늘 한 일·고민과 판단·확인 결과와 막힌 점·다음 할 일을 짧게 적어줘.
관련 이슈·PR·설계 문서·ADR이 있으면 링크를 연결해줘.
확인되지 않은 이유나 결과를 만들지 말고 미확인·미실행을 구분해줘.
지금 떠올린 대안을 당시 검토한 대안처럼 쓰지 마.
중요한 결정은 ADR 분리 후보로 알려줘.
AI로 작성한 부분은 담당자 확인 전이라고 표시하고, 미확인 결과를 완료·채택으로 표시하지 마.
PR 설명에 넣을 문서 링크도 정리해줘.
```
