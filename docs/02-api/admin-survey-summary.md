# GD-223·GD-271 관리자 설문 응답 집계와 자유 서술 답변 조회

- 작업 브랜치: `feat/GD-223`(집계), `feat/GD-271`(자유 서술 답변 조회)
- 배경: 관리자 대시보드의 설문 추이를 보여 주기 위한 프론트 요청 R5. 지금은 응답 수만 지급 이력(AO03)의 `missionId`로 우회해 셀 수 있고 선택지별 답변은 볼 수 없다.
- 공용 스펙 [미션 API](https://github.com/Uplus-GETDDO/getddo-spec/blob/main/05-api/mission.md)에 AM04 제안으로 올라와 있다. 경로와 필드는 프론트 요청 문서의 제안을 따랐고 확정 전이다.

## 경로

`GET /api/v1/admin/missions/{missionId}/survey-summary?from=2026-10-11&to=2026-10-17`

활성 ADMIN만 호출할 수 있고 아니면 403 `MISSION-006`이다.

| 파라미터 | 설명 |
| --- | --- |
| `from` | KST 시작 날짜(포함), `YYYY-MM-DD`. 필수 |
| `to` | KST 끝 날짜(포함), `YYYY-MM-DD`. 필수. 시작 날짜와 같거나 이후이고 양끝을 포함해 최대 31일 |

응답은 공통 성공 봉투(`success`, `data`) 안에 담긴다. 예시는 `from=2026-10-11&to=2026-10-17` 요청이다.

```json
{
  "success": true,
  "data": {
    "dailyResponses": [
      { "date": "2026-10-11", "count": 0 },
      { "date": "2026-10-12", "count": 4 },
      { "date": "2026-10-13", "count": 0 },
      { "date": "2026-10-14", "count": 2 },
      { "date": "2026-10-15", "count": 0 },
      { "date": "2026-10-16", "count": 1 },
      { "date": "2026-10-17", "count": 0 }
    ],
    "questions": [
      { "questionId": "…", "questionText": "…",
        "options": [
          { "optionId": "…", "optionText": "…", "count": 5 },
          { "optionId": "…", "optionText": "…", "count": 2 }
        ] }
    ]
  }
}
```

## 규칙

- **완료된 제출만** 센다. `dailyResponses`는 완료된 설문 제출 수를 제출 시각의 KST 날짜별로 센다. 응답이 없는 날도 `count: 0`으로 담아 기간의 모든 날짜가 나온다.
- `questions`는 **선택형(단일 선택) 문항만** 담는다. 자유 서술 문항은 집계하지 않는다. 문항과 선택지는 표시 순서 오름차순이고, 고른 사람이 없는 선택지도 `count: 0`으로 담는다. 선택지별 수는 같은 기간에 완료된 제출의 답변만 센다.
- 날짜별 제출 수와 선택지별 응답 수는 같은 반복 가능한 읽기 스냅샷에서 구한다.
- 오류는 조건마다 코드 하나다.
  - 활성 관리자가 아님: 403 `MISSION-006`
  - `from` 또는 `to`가 없음: 400 `COMMON-002`
  - 날짜 형식이 `YYYY-MM-DD`가 아님: 400 `COMMON-005`
  - `to`가 `from`보다 앞섬, 또는 양끝을 포함한 기간이 31일을 넘음(`to - from`이 31일 이상. `from`과 `to`가 같은 하루는 허용): 400 `MISSION-001`. 기간 규칙은 서비스 한 곳에서만 검사하므로 코드가 하나다
  - 없는 미션: 404 `MISSION-003`
  - 설문이 아닌(퀴즈) 미션: 400 `MISSION-001`

## 판단과 제약

- 기간을 필수로 한 것은 요청 문서의 예시(`from`, `to` 둘 다 지정)를 따른 것이다. 생략 시 기본 기간은 정하지 않았다.
- 퀴즈 미션에 대한 오류는 새 코드를 만들지 않고 기존 `MISSION-001`(미션 구성 오류)을 썼다. 메시지가 정확히 들어맞지는 않는다.
- 제출 시각은 UTC로 저장돼 있어 KST 날짜는 +9시간으로 환산해 묶는다(KST는 서머타임이 없다). 집계는 `mission_submissions`와 `survey_answers`를 `mission_id`, 제출 시각 범위로 읽는다. 데이터가 많아지면 `EXPLAIN`으로 확인하고, 필요하면 제출 시각 인덱스를 새 마이그레이션으로 추가한다. 성능은 측정하지 않았다.
- 집계(R5)는 자유 서술 답변 내용을 담지 않는다. 답변 원문은 아래 AM05로 따로 조회한다. 긍정/부정 묶음은 프론트가 선택지를 묶어 표시한다.
- 읽기 전용이라 감사 기록 대상이 아니다.

## 자유 서술 답변 조회 (AM05, GD-271)

`GET /api/v1/admin/missions/{missionId}/survey-answers?questionId=…&from=2026-10-11&to=2026-10-17&page=1&size=20`

설문 미션의 자유 서술 문항에 완료된 제출이 남긴 답변을 제출 시각 최신순(같으면 답변 ID 내림차순)으로 조회한다. 활성 ADMIN만 호출할 수 있고 아니면 403 `MISSION-006`이다. 읽기 전용이다.

| 파라미터 | 설명 |
| --- | --- |
| `questionId` | 이 미션의 자유 서술 문항 ID. 필수 |
| `from`, `to` | 집계(R5)와 같은 KST 날짜 규칙. 필수. 양끝 포함 최대 31일 |
| `page`, `size` | 1부터, 기본 `1`·`20`, 크기 1~100 |

응답은 공통 성공 봉투 안의 페이지(`items`, `page`, `size`, `totalElements`)이고 항목은 두 필드뿐이다.

```json
{ "answerText": "집에 가고 싶다", "submittedAt": "2026-10-12T01:00:00Z" }
```

- **익명**이다. 사용자·제출 식별자와 이름은 응답에도 쿼리에도 담지 않는다. 답변 원문은 가공하지 않고 돌려주므로 화면에서 HTML로 해석하지 않아야 한다.
- 완료된 제출의 답변만 담는다. 답변이 비어 있는(선택 문항을 건너뛴) 제출은 담지 않는다.
- 오류: 활성 관리자가 아님 403 `MISSION-006`, 필수값 누락·페이지 크기 범위 밖 400 `COMMON-002`, 날짜·UUID 형식 오류 400 `COMMON-005`, 없는 미션 404 `MISSION-003`, 설문이 아닌 미션·이 미션의 자유 서술 문항이 아닌 `questionId`(선택형 문항·다른 미션의 문항 포함)·기간 규칙 위반 400 `MISSION-001`.
- 목록과 전체 건수 두 조회를 같은 반복 가능한 읽기 스냅샷에서 구한다. 정렬은 제출 시각 내림차순이다. 데이터가 많아지면 `survey_answers(survey_question_id)`와 제출 시각 조건을 `EXPLAIN`으로 확인하고 필요하면 새 마이그레이션으로 인덱스를 추가한다. 성능은 측정하지 않았다.
- 이 API는 내용을 모아 보여 줄 뿐이며 개인정보 마스킹은 하지 않는다. 사용자가 답변에 직접 쓴 개인정보는 그대로 노출될 수 있다.

## 검증

- 단위: `SurveySummaryServiceTest`(권한, 기간 검증, 0건 날짜·선택지 채우기, 자유 서술 제외, 퀴즈·없는 미션, 자유 서술 답변 조회의 권한·기간·문항 검증), `AdminSurveySummaryControllerTest`(응답 구조, 누락·형식 오류 코드, 오류 코드 매핑, 익명 답변 응답에 식별자 필드가 없음).
- 실제 MySQL(AM05): `SurveySummaryIntegrationTest`가 KST 날짜 경계로 답변을 거르고 최신순으로 돌려주는지, 페이지 분할과 범위를 넘는 페이지, 미완료 제출·다른 설문의 답변 제외, 선택형·다른 미션 문항 거절을 확인한다.
- 실제 MySQL: `SurveySummaryIntegrationTest`(KST 자정 직전·직후 제출이 서로 다른 날짜로 집계됨, 시작 날짜 00:00 포함·직전 제외·끝 날짜 다음 날 00:00 제외·직전 포함, 기간 밖 제출 제외, 범위 안에 저장된 미완료 제출의 답변 제외, 선택지별 건수, 31일 기간 허용과 32일째 거절, 다른 설문과 섞이지 않음, 퀴즈·없는 미션 거절).
