# GD-223 관리자 설문 응답 집계

- 작업 브랜치: `feat/GD-223`
- 배경: 관리자 대시보드의 설문 추이를 보여 주기 위한 프론트 요청 R5. 지금은 응답 수만 지급 이력(AO03)의 `missionId`로 우회해 셀 수 있고 선택지별 답변은 볼 수 없다.
- 공용 스펙 [미션 API](https://github.com/Uplus-GETDDO/getddo-spec/blob/main/05-api/mission.md)에 AM04 제안으로 올라와 있다. 경로와 필드는 프론트 요청 문서의 제안을 따랐고 확정 전이다.

## 경로

`GET /api/v1/admin/missions/{missionId}/survey-summary?from=2026-10-11&to=2026-10-17`

활성 ADMIN만 호출할 수 있고 아니면 403 `MISSION-006`이다.

| 파라미터 | 설명 |
| --- | --- |
| `from` | KST 시작 날짜(포함), `YYYY-MM-DD`. 필수 |
| `to` | KST 끝 날짜(포함), `YYYY-MM-DD`. 필수. 시작 날짜와 같거나 이후이고 양끝을 포함해 최대 31일 |

응답은 공통 성공 봉투(`success`, `data`) 안에 담긴다. 예시는 `from=2026-10-11&to=2026-10-17` 요청이다.

```json
{
  "success": true,
  "data": {
    "dailyResponses": [
      { "date": "2026-10-11", "count": 0 },
      { "date": "2026-10-12", "count": 4 },
      { "date": "2026-10-13", "count": 0 },
      { "date": "2026-10-14", "count": 2 },
      { "date": "2026-10-15", "count": 0 },
      { "date": "2026-10-16", "count": 1 },
      { "date": "2026-10-17", "count": 0 }
    ],
    "questions": [
      { "questionId": "…", "questionText": "…",
        "options": [
          { "optionId": "…", "optionText": "…", "count": 5 },
          { "optionId": "…", "optionText": "…", "count": 2 }
        ] }
    ]
  }
}
```

## 규칙

- **완료된 제출만** 센다. `dailyResponses`는 완료된 설문 제출 수를 제출 시각의 KST 날짜별로 센다. 응답이 없는 날도 `count: 0`으로 담아 기간의 모든 날짜가 나온다.
- `questions`는 **선택형(단일 선택) 문항만** 담는다. 자유 서술 문항은 집계하지 않는다. 문항과 선택지는 표시 순서 오름차순이고, 고른 사람이 없는 선택지도 `count: 0`으로 담는다. 선택지별 수는 같은 기간에 완료된 제출의 답변만 센다.
- 날짜별 제출 수와 선택지별 응답 수는 같은 반복 가능한 읽기 스냅샷에서 구한다.
- 오류는 조건마다 코드 하나다.
  - 활성 관리자가 아님: 403 `MISSION-006`
  - `from` 또는 `to`가 없음: 400 `COMMON-002`
  - 날짜 형식이 `YYYY-MM-DD`가 아님: 400 `COMMON-005`
  - `to`가 `from`보다 앞섬, 또는 두 날짜 사이가 31일을 넘음(`from`과 `to`가 같은 하루는 허용): 400 `MISSION-001`. 기간 규칙은 서비스 한 곳에서만 검사하므로 코드가 하나다
  - 없는 미션: 404 `MISSION-003`
  - 설문이 아닌(퀴즈) 미션: 400 `MISSION-001`

## 판단과 제약

- 기간을 필수로 한 것은 요청 문서의 예시(`from`, `to` 둘 다 지정)를 따른 것이다. 생략 시 기본 기간은 정하지 않았다.
- 퀴즈 미션에 대한 오류는 새 코드를 만들지 않고 기존 `MISSION-001`(미션 구성 오류)을 썼다. 메시지가 정확히 들어맞지는 않는다.
- 제출 시각은 UTC로 저장돼 있어 KST 날짜는 +9시간으로 환산해 묶는다(KST는 서머타임이 없다). 집계는 `mission_submissions`와 `survey_answers`를 `mission_id`, 제출 시각 범위로 읽는다. 데이터가 많아지면 `EXPLAIN`으로 확인하고, 필요하면 제출 시각 인덱스를 새 마이그레이션으로 추가한다. 성능은 측정하지 않았다.
- 자유 서술 답변 내용은 이번 요청에서 제외했다. 긍정/부정 묶음은 프론트가 선택지를 묶어 표시한다.
- 읽기 전용이라 감사 기록 대상이 아니다.
