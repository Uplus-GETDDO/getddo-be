# 이벤트·경품 수정 — GD-60

- 상태: 검토 대기 — 구현·연동 설명, 담당자 확인 전
- 공용 기준: [이벤트 도메인 규칙](https://github.com/GETDDO/getddo-spec/blob/main/02-domain/event.md), [AE04 요청·응답](https://github.com/GETDDO/getddo-spec/blob/main/05-api/event.md)

`PUT /api/v1/admin/events/{eventId}`는 기존 `EventWriteRequest`로 전체 설정·경품 목록을 받고 `AdminEventResponse`를 반환한다. UUID 변환·DTO 형식 검증은 Controller, 관리자 확인·수정 제한·설정 검증과 알림 연동은 `EventModificationService`가 처리한다.

## 수정과 경품 교체

- 이벤트·경품을 잠금 읽기한 후 현재 시각을 확인한다. `SCHEDULED`이며 기존 시작 시각 전인 미삭제 이벤트만 수정한다. 시작 시각은 유지하거나 늦출 수 있다.
- 등록과 수정은 `EventWriteValidator`의 마이크로초 정규화, 기간 범위, 응모 조건, 문자열·TEXT 바이트 상한과 경품 중복 검증을 공유한다.
- 유지할 경품은 기존 `id`, 새 경품은 `id:null`로 전달한다. 누락한 기존 경품은 제거하고 다른 이벤트·존재하지 않는 경품 ID는 거절한다. 등록 요청에서는 경품 ID를 허용하지 않는다.
- 경품 ID의 등록 허용 여부와 수정 소유권은 Service에서 업무 오류로 검증한다. DTO의 변환 메서드는 업무 검증 없이 값을 옮기고, Entity의 소유권 확인은 컬렉션 변경 전 호출 계약을 보호하는 `IllegalArgumentException` 방어 검사다.
- 같은 이벤트의 등수를 교환할 때 유지할 경품을 비어 있는 양수 등수로 옮기고 중간 flush 후 최종 등수를 적용한다. 기존 ID·생성 시각을 유지하고 UNIQUE·CHECK 제약을 만족하며 두 단계는 같은 트랜잭션이다.
- 기존 경품 ID와 전체 설정이 같은 PUT은 저장을 생략한다. ID 없는 경품은 등수·이름·설명이 같아도 항상 새 경품으로 등록하며, 요청 목록에서 빠진 기존 ID의 경품은 제거한다. 새 경품 등록 후 다음 수정에는 응답으로 받은 ID를 사용한다. `id:null`을 그대로 재전송하면 새 ID를 다시 발급하며, 요청 자체를 구분하는 별도 중복 방지 계약은 제공하지 않는다.

| 오류 | HTTP | 의미 |
| --- | --- | --- |
| EVENT-011 | 409 | 진행 예정이 아니거나 기존 시작 시각에 도달한 이벤트 |
| EVENT-012 | 409 | 기존 시작 시각보다 앞당기는 요청 |
| EVENT-004 | 400 | 경품 구성·중복 ID·현재 이벤트에 속하지 않은 ID |
| EVENT-007 | 404 | 없거나 삭제된 이벤트 |

저장소는 먼저 이벤트 행을 잠근 뒤 경품을 함께 잠금 조회한다. Hibernate 7.4의 기본 잠금 범위는 조회 루트에만 적용되어, MySQL의 REPEATABLE READ에서 경품을 이전 스냅샷으로 읽을 수 있다. 따라서 이 조회만 `INCLUDE_FETCHES` 범위를 지정한다. 실제 동시 PUT 테스트에서 이벤트·경품 양쪽 잠금과 중복 변경 안내 방지를 검증한다. 현재 범위 API는 향후 JPA 4로 전환할 때 대체해야 한다.

GD-321의 선택 `detailImageKey`도 전체 설정 비교와 변경 전후 감사 스냅샷에 포함한다. 생략·null은 이미지 연결 제거이며, 유지할 때는 기존 키를 재전송한다. 응답과 업로드 방법은 [상세 설명 이미지](event-images.md#이벤트-상세-설명-이미지--gd-321)를 따른다.

## GD-70 알림 연동

실제 시작 시각 연기에만 이벤트·경품 최종 flush 후 `EventChangeNotificationService.register(EventNotificationChange.scheduleChanged(...))`를 호출한다. 제목·설명·경품만 바뀌면 일정 변경 알림은 등록하지 않는다. 알림 등록 실패는 이벤트·경품과 이전 시작 작업 중지를 함께 롤백한다.

실제 시작 연기에 서버가 부여하는 UUID와 최초 발생 시각·이전/새 시작 시각은 알림 작업의 발생 키·payload에 보존한다. 이벤트 행 잠금 안에서 기존·요청 시작 시각을 비교하므로, 같은 일정 변경의 동시 실행·재전송은 새로운 변경 알림을 만들지 않는다. 이는 경품의 신규 등록 여부와 별개이며, 알림 워커가 재처리할 때는 저장된 발생 키와 payload를 사용한다.

시작 예약·기존 수신자 고정·비동기 안내 처리의 상세 기준은 [알림 워커 운영 문서](../06-runbook/notification-worker.md#일정-변경취소-안내--gd-70)를 따른다. 이벤트 삭제·취소와 응모권 반환은 별도 업무 서비스가 처리한다.

GD-203에서 변경 전후 설정·경품을 `EVENT_UPDATE` 공통 감사 기록으로 남긴다. 동일 설정의 재전송은 감사 기록도 추가하지 않는다. 감사 실패는 이벤트·경품·일정 변경 안내를 함께 롤백한다. 응답의 추첨 시각 필드 변경은 [모집 상태·감사 문서](event-lifecycle-and-audit.md)를 따른다.
