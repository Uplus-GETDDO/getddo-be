# API 내부 처리 흐름

- 상태: 검토 대기 — 담당자 확인 전

브라우저가 직접 호출하지 않는 처리와 도메인 간 연동 경계를 정리한다. 업무 정책은 `getddo-spec/02-domain`, 외부 요청·응답은 `getddo-spec/05-api`를 기준으로 한다.

| 처리 | 트리거·경계 |
| --- | --- |
| 이벤트 개시·마감 | GD-203 워커가 서버 시각으로 SCHEDULED→OPEN→CLOSED를 반영한다. 이벤트 잠금·감사 원자성과 장애 후 복구는 [구현 문서](event-lifecycle-and-audit.md)를 따른다. 응모 요청의 기간 검사는 별도로 유지한다 |
| 최초 추첨·발표 | 마감 +1분 자동 추첨 후 관리자 확인·별도 수동 공개. 고정 발표 예정 시각이나 자동 공개는 제공하지 않는다. 실제 공개 후 상태 연결은 GD-199의 추첨 담당 범위다 |
| 이벤트 취소 | GD-202의 `EventCancellationService`가 이벤트를 쓰기 잠금으로 읽고 취소·차감 응모별 `TicketRefundService` 반환·GD-70 취소 안내 등록·감사 기록을 같은 트랜잭션에서 처리한다. 자세한 경계는 [취소 구현](event-cancellation.md)을 따른다. 일시 중단·재개는 제공하지 않는다 |
| 응모권 만료 | 만료 시각이 지난 사용 가능 응모권을 만료됨으로 바꾸고 `EXPIRE` 이력을 남김. 사용 완료 응모권은 만료하지 않음 |
| 정책 적용 | 다음 KST 일/월 기준일부터 새 정책 적용 |
| 시작 알림 | 시작 10분 전 자격 충족 사용자에게 1회. 일정 변경은 예약 갱신·이미 수신한 사용자 안내 |
| 결과 알림 | 타이머 종료가 아닌 실제 공개/명단 갱신에 연동 |
| 자동 재시도 | 알림 중복 생성 방지 및 최종 실패 운영 조회 |
| 탐지·검토 연계 | 지급·응모 요청 탐지와 확정 검토. 응모권 회수는 공용 명세에 따라 이번 버전에서 제외 |

브라우저 호출로 내부 배치·최초 추첨을 직접 실행하거나 잔액을 직접 지정하는 API는 두지 않는다. 출석·응모 등 사용자 업무 요청이 정당한 지급·차감을 발생시키는 것은 해당 업무 계약을 따른다. 스케줄러나 비동기 구현 기술은 이 문서에서 선택하지 않는다.

## 구현 상태

기능별로 구현 범위가 다르다. 구현된 업무 API는 실행 중인 서버의 OpenAPI 문서([API 안내](README.md)의 `/swagger-ui.html`)와 공용 계약(`getddo-spec/05-api`)을 대조하고, 미션처럼 서비스·저장소만 있는 기능은 해당 Jira 이슈와 PR 본문을 기준으로 확인한다. 이 표의 내부 처리 중 응모권 만료 워커는 구현되어 있다([런북](../06-runbook/ticket-expiry-worker.md)).
