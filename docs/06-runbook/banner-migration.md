# GD-209 배너 이전·공개 이미지 설정 확인

- 상태: 검토 대기 — 실제 운영 DB 확인·배포 미실행
- 구현·검증 명령: [배너 안내](../02-api/banners.md)

## 배포 전

1. 담당자가 실제 DB에서 banners의 ID·event_url·image_key·display_order·시각을 확인하고 백업한다. 비공개 주소·개인정보·비밀값을 작업 문서에 복사하지 않는다.
2. V028 번호가 공유 dev/서버에서 비어 있는지 확인한다. 기존 적용 마이그레이션을 수정하지 않는다.
3. 공개 이미지 기준 주소는 기존 `GETDDO_IMAGES_BASE_URL`에 주입한다. S3 bucket 접근 주소와 구분한다. 실제 키로 CDN 이미지를 읽을 수 있는지 별도 확인한다.
4. Flyway로 V028을 적용한 뒤 `banners.event_id` nullable/FK와 `banner_catalog_lock`의 id=1을 확인한다. 기존 행·URL·순서·시각이 보존됐는지 대조한다.

## 이전 행 처리

미연결 이전 배너는 공개 API에 나오지 않고 관리자 목록에서 eventId=null이다. 올바른 이벤트를 확인한 관리자가 수정으로 연결한다. URL 파싱·가짜 UUID·일괄 삭제로 채우지 않는다. 숨김 행도 다섯 개에 포함되므로 신규 등록이 막히면 관리자 목록을 먼저 확인한다. 이전 순서에 구멍이 있어도 이전 작업에서 덮어쓰지 않으며 이후 관리 변경에서 1~N으로 정리한다.

## 실패 확인·복구

공개 주소 설정 오류는 변경 전에 실패한다. BANNER-005는 목록을 다시 조회한 뒤 전체 ID로 재요청한다. 감사/DB 실패는 해당 Service 트랜잭션 전체가 롤백되므로 순서·기존 URL·감사 행을 대조한다. 서버 설정/DB 복구는 담당자 절차를 따르며 운영 행을 수동 재삽입하거나 잠금 제어 행을 삭제하지 않는다.

이전 migration rollback SQL을 자동 실행하지 않는다. 애플리케이션 rollback 시에도 추가 컬럼·제어 테이블·기존 데이터를 보존한 채 담당자가 이전/현재 버전의 호환성을 확인한다.
