### 프론트 화면 지연 원인 확인과 요청 (BE 변경 없음)

- 홈의 "퀴즈·설문" 버튼이 새로고침 뒤 한참 있다가 "완료"로 바뀌는 원인을 확인했다. M01은 사용자별 `completed`를 매번 정확히 계산해 주고, 프론트가 미션 목록을 50개씩 순서대로 끝까지 받은 뒤에야 판정한다. 테스트 데이터 미션이 약 4,000개(`page=81`까지 확인)라 81번 연속 호출이 끝나야 바뀐다.
- 마이페이지 응모권 내역이 느린 이유도 확인했다. T02는 호출 한 번에 목록 쿼리와 전체 건수 쿼리를 모두 실행하고, 프론트가 건수만 얻으려고 `size=1`로 여러 번 부른다. 사용자당 응모권이 4,000장이라 두드러진 것이며 200장 수준에서는 문제가 아니다.
- 관리자 이벤트 관리의 "응모 시작일" 검색이 400 `COMMON-005`인 것을 화면에서 직접 확인했다. AE01의 `from`/`to`는 `YYYY-MM-DD`만 받는데 프론트가 시작일을 ISO 시각으로 보낸다(등록일은 날짜로 보내서 200). 서버는 정상이다.
- 위 세 건을 프론트에 요청으로 전달했다(미션 목록 조회 정리, 응모권 이력 건수 호출 정리, 시작일 형식). 데이터는 시연용으로 다시 넣을 예정이다.
- 사용자 이벤트 목록(`GET /v1/events`)에 날짜 조건이 없는 것은 스펙에서 의도한 것이고, 관리자 목록(AE01)에만 있다.
