## 고민과 판단

- `SKIP LOCKED`의 속도 차이를 정합성 근거처럼 쓰지 않기로 했다. 일반 잠금도 중복 0이므로 발표에서는 "대기 시간 약 3.3배 단축, 일반 잠금은 교착 가능성도 있다"로 쓴다. README의 20.9초 대 3.5초와 값이 달라 문구를 맞춰야 한다.
- 정합성은 DB 유일 제약과 행 잠금이 이중으로 지킨다. 한쪽을 빼도 데이터는 오염되지 않거나 다른 쪽이 막지만, 응모권 행 잠금이 없으면 요청이 500으로 실패한다. 잠금의 역할을 "오염 방지"가 아니라 "경합을 직렬로 성공시키는 것"으로 설명한다.
- 개발 서버 2대 대상 측정은 하지 않았다. 서버 2대 전환이 진행 중이고 `RATE_LIMIT_STORE` 값을 확인하지 못했으며, 공유 DB에 쓰기가 발생해서다. 보고서에는 한계로 적었다.
- 결과 보고서의 위치는 GD-254(#143)가 `docs/07-verification/`과 `docs/templates/verification-report.md`를 추가하는 방식과 맞추는 쪽이 낫다고 보았다. 병합되면 템플릿 형식으로 옮긴다.

## 확인 결과 / 막힌 점

- 실행: 위 측정은 모두 실제 MySQL(Testcontainers 또는 일회용 Docker)에서 돌렸고 결과는 숫자로 기록했다. 노트북 한 대의 상대 비교이며 절대 속도가 아니다. 전체 `./gradlew build`는 돌리지 않았다.

- 메모리 부족으로 배치 실행 2개가 중단됐다. 반복은 단독으로 나눠 다시 돌렸다.
- 미측정·미확인: 쓰기 API 3개의 프론트 연동, 정합성 서랍, 서버 2대(실제 EC2)와 `RATE_LIMIT_STORE` 값, 커밋 뒤 응답 유실(프로세스 강제 종료), 마감 직전 커밋 간격(GD-205), 응답 시간·처리량. 미션 동시 중복 제출에서 확인한 실행의 192건 중 0~3건이 400(`INVALID_MISSION_ANSWER`)이었다. 원인은 코드를 읽어 추정했을 뿐 확정하지 못했다.
- 요청할 것: 이경주에게 `RATE_LIMIT_STORE` 값, 서버 대수, ALB 접근 범위, WAF 연결과 Terraform 위치를 확인한다. 송동현에게 정합성 탭 처리와 이력 폴링, Vercel 중계 구조의 IP 영향을 확인한다. 전민규에게 게임 통계 대조 SQL의 유효 플레이 정의를 확인한다.
