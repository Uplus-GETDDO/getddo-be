### 멘토링 대비

- 예상 질문을 정리했다. ERD에서 응모권 구조를 바꾼 이유, 교착 경험, 마감 판정의 틈, 측정의 한계를 다뤘고, 질문 투를 더 간단하게 다듬었다.
- 응모 한 건의 트랜잭션 경계를 문서로 정리했다. 응모 처리는 `EntryRecorder.record` 한 트랜잭션이고 응모권 차감은 거기에 합류한다. 마감은 차감 직후와 커밋 직전(`beforeCommit`)에 두 번 확인하는데, 두 번째 확인 뒤 SQL 3개를 보내고 커밋이 확정되기까지가 막을 수 없는 틈이다. 임시 테스트로 한 건을 실행해 SQL 전송 순서를 확인했고(그 구간이 약 11ms, 한 번 본 값이라 보장 값이 아니다) 테스트는 저장소에 남기지 않았다.

### 관리자 API 구현 (멘토링 뒤 미뤄 두었던 것)

- **AO06·AO07 (GD-218, PR #118, 병합)**: 관리자 응모 내역(`GET /admin/entries`)과 이벤트 응모자(`GET /admin/events/{eventId}/participants`)를 만들었다. 사용자 응모 이력 쿼리를 사용자 조건만 선택으로 바꿔 함께 쓴다. 활성 관리자가 아니면 403 `ENTRY-010`을 새로 추가했다. `event_entries` 10만 행에서 사용자 조건 없는 조회가 전 행을 정렬했고 첫 페이지가 약 40ms였다(한 번 잰 값). 관리자 화면 규모라 인덱스는 추가하지 않고 문서에 남겼다.
- **AP01~AP04 (GD-219, PR #119, 병합)**: 일일·연속 출석 정책 조회와 등록이다. 적용 시점은 입력받지 않고 서버가 다음 KST 자정, 다음 KST 월 1일로 계산한다. 일일 정책 등록은 열린 정책을 `FOR UPDATE`로 잠가 읽고, 이전 정책 종료를 먼저 DB에 반영한 뒤 새 정책을 저장한다(`reward_policies`는 종료 시각이 없는 출석 정책을 하나만 허용하므로 순서가 바뀌면 저장이 실패한다). 같은 적용일·적용월 중복은 409, 단계 순서·중복·범위 위반은 400이다. 정책 등록은 감사 기록을 남긴다. 담당 문서에 관리자 정책 API가 전민규 항목에도 있어 구현 사실을 알려야 한다.
- **AM01~AM03 (GD-177, PR #120, 병합)**: 관리자 미션 목록·상세·등록이다. 초안(DRAFT) 상태는 두지 않고 등록하면 바로 ACTIVE로 했다. 미션 보상은 응모권 1장 고정이라 `rewardTicketCount`는 생략하거나 1만 받고, 미션마다 수량 1의 보상 정책을 만들어 연결한다. 선택형 퀴즈는 선택지 2개 이상에 정답이 정확히 하나여야 한다는 규칙은 스펙에 정해진 값이 없어 이 구현에서 정했다.
- 세 PR 모두 통합 테스트는 PR에 넣지 않았다. 저장소 SQL은 임시 MySQL 테스트로 한 번씩 확인했고 그 테스트는 지웠다.

### 프론트 요청 R1~R7 검토와 구현

- 요청 문서의 R1~R7을 영역별로 나눠 검토했다. R5(설문 응답 집계)와 R7(이벤트 목록의 내 응모 여부)이 내 몫이고, R1(관리자 일별 집계)은 응모·응모권 집계만 내 소유라 도메인별로 나눌지 한 API로 묶을지, `activeUserCount`의 참여 범위를 어디까지 볼지 회의에서 정해야 한다. R2·R4는 박지훈, R3은 이경주, R6은 석종수 몫이다.
- **R5 (GD-223, PR #122, 진행 중)**: `GET /admin/missions/{missionId}/survey-summary?from&to`로 날짜별 완료 제출 수와 단일 선택 문항의 선택지별 응답 수를 집계한다. 날짜는 KST 기준이고 기간은 필수에 최대 31일이다. 응답 없는 날과 선택지도 0건으로 담는다. CodeRabbit 지적 중 기간 검증 중복, null 계약, 오류 코드 테스트, 문서 응답 예시를 고쳤고, 지적에 따라 실제 MySQL 통합 테스트(KST 자정 경계, 기간 경계, 미완료 제출 제외, 31일 허용 등 5건)를 추가했다.
- **R7 (GD-224, PR #123, 닫음)**: 응모 도메인의 조회 기능을 만들었으나, 박지훈의 PR #124가 같은 `myEntered`를 이벤트 쪽에서 직접 구현하고 있어 중복이라 닫았다. 판정 기준(접수된 응모가 있어야 응모한 것, 거절만 있으면 아님)은 같고, 스펙 `entry.md`의 R7 절은 이벤트 계약에서 처리하는 것으로 고쳤다. `myEntered`는 이벤트가 취소되어 응모권이 반환된 뒤에도 true로 남으므로 프론트와 의미를 맞춰야 한다.
