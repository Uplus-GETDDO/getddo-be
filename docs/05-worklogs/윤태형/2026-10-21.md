### 관리자 응답에 이름 추가 (GD-284, PR #153, 진행 중)

- 스펙의 ADR-028(관리자 응답의 사용자·처리자 이름)에 따라, 내 영역의 관리자 응답에 ID는 그대로 두고 현재 이름을 더했다. AO06·AO07·AO04에는 `userName`, AM01~AM03과 AP01~AP06에는 `createdByName`이다. 이름은 저장하지 않고 요청 시점의 `users.name`이며, ID가 null이거나 사용자 행이 없으면 null이다.
- `UserNameRepository.findNamesByIds`로 목록 전체를 한 번에 읽어 N+1을 피한다. `UserRepository`에 메서드를 더하지 않은 것은 컨트롤러 테스트가 그 인터페이스를 람다로 쓰고 있기 때문이다. 서비스는 값과 이름을 묶은 `NamedValue<T>`를 돌려주고 응답 DTO가 펼친다. 추첨·알림 응답은 각 담당자 범위라 건드리지 않았고, 같은 조회를 재사용할 수 있다.
- 출석 정책 수정(AP05·AP06)의 `createdByName`은 수정자가 아니라 정책을 만든 관리자의 이름이다.
- 테스트는 서비스 4개·컨트롤러 4개에 이름 단언을 더했고, 실제 MySQL 통합 테스트 3개(`AdminEntryNamesIntegrationTest`, `AdminMissionNamesIntegrationTest`, `AdminAttendancePolicyNamesIntegrationTest`)로 이름이 `users.name`과 같고, 이름을 바꾸면 다음 조회에 반영되며, 없는 ID는 담기지 않는 것을 확인했다.
- 첫 푸시에서 CI `빌드·테스트`가 실패했다. 석종수의 `EntrySnapshotIntegrationTest` 15건이 컨텍스트 로드 단계에서 `NoSuchBeanDefinitionException`으로 깨졌다. 이 테스트 설정이 응모 패키지를 통째로 스캔하는데, 거기 들어온 `AdminEntryQueryService`가 새로 요구하는 `UserNameRepository` 빈이 없었다. 석종수 영역 파일 `EntrySnapshotTestApplication`에 빈 맵을 돌려주는 빈 하나를 더해 고쳤다.
- CodeRabbit 지적 2건도 코드로 고쳤다. 출석 정책에서 작성자 행이 없을 때 `createdByName`이 null인 경계 단위 테스트 2개를 추가했고, 응모 조회 문서의 "통합 테스트 없음"과 이름 통합 테스트 설명이 모순이던 문장을 바로잡았다. 스레드 답글과 닫기는 아직 하지 않았다.

## 고민과 판단

- 이름은 저장하지 않고 조회 시점의 현재 이름을 쓴다. 퇴사·개명 후 과거 응답이 바뀌는 단점이 있지만, 관리자 화면 표시용이고 ID로 식별은 그대로 된다는 ADR-028의 결정을 따랐다.
- 이름 조회를 `UserRepository`와 분리한 것은 기존 테스트의 람다 구현을 깨지 않기 위한 선택이다. 대신 석종수의 테스트 설정에 스텁 빈을 더하는 부수 변경이 생겼고, PR 설명에 적어 알린다.
- 예약 정책 수정은 취소(삭제)와 적용 시점 변경을 제공하지 않기로 했다. 필요하면 별도 결정이다.
