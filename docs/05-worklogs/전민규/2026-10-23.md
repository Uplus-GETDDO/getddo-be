## 확인 결과 / 막힌 점

검증 기준은 `dev`의 `f588f201dfbb42c025426bdfe98196b384b66e7d` 임시 사본이다.

| 항목 | 1,000건 | 10,000건 |
| --- | ---: | --- |
| 등록 수신자 / 작업 | 1,000명 / 1개 | 10,000명 / 1개 |
| 생성 알림 | 1,000건 | 0건 |
| 중복·누락 | 모두 0건 | 생성 미진입으로 완료 검증 불가 |
| 모의 발송 성공 / 최종 실패 | 997건 / 3건 | 발송 미진입 |
| 총 발송 시도 / 재시도한 알림 | 1,237회 / 193건 | 발송 미진입 |
| 생성 완료 관측 | 18.289초 | 완료되지 않음 |
| 자동 처리 종료 관측 | 201.049초 | 완료되지 않음 |

- **1,000건:** 지정한 통합 테스트 1개가 통과했다. 모든 알림이 미읽음을 유지하고, 시도 횟수는 1~4회였다. 같은 작업을 재등록해도 알림이 늘지 않았다. Gradle은 `BUILD SUCCESSFUL`이며 준비·빌드를 포함해 5분 12초 걸렸다. 전체 프로젝트 테스트·빌드 통과를 의미하지 않는다.
- **10,000건:** `NotificationJobRepositoryImpl.claimNextJob()`의 선점 SELECT에서 `HY001 / 1038: Out of sort memory`가 반복됐다. 작업은 `PENDING`, 시도 횟수는 0이었다. 동일 오류 반복을 확인해 실행을 중단했으며 정상 완료나 테스트 통과로 기록하지 않는다.
- 오류 당시 작업 JSON은 400,129바이트, 테스트 MySQL의 `sort_buffer_size`는 262,144바이트였다. 큰 수신자 JSON과 정렬을 함께 다루는 쿼리가 조사 대상이다. 실행 계획과 버퍼 설정별 비교는 아직 하지 않았으므로 이 수치만으로 내부 원인을 확정하지 않는다.
- 운영 코드·DB 설정은 바꾸지 않았고 두 실행의 임시 컨테이너 종료를 확인했다. 테스트 소스·결과 JSON·DB 조회 증거·오류 로그는 로컬 `바탕화면/프로젝트 설명용/알림1000건_검증_2026-10-23`, `알림10000건_검증_2026-10-23`에 보관했다.
- 관리자 복구, CPU·메모리·DB 부하, 두 API 서버 동시 처리 및 AWS 스테이징 실행은 이번 검증에 포함하지 않았다. 100,000건은 실행하지 않았다.

실행 명령은 각각 다음과 같다. 테스트 클래스는 임시 사본에만 추가했다.
