# 2026-10-25

- 기록 근거: [24일 워크로그의 25일 후속 보완](2026-10-24.md#2026-10-25-후속-보완--특정-이벤트-마감-전후-혼합-트래픽). 기존 기록은 보존하고 날짜별로 찾아볼 수 있도록 정리했다.

## 오늘 한 일

- 특정 이벤트 마감 전후에 조회·응모·출석·게임·미션 요청이 함께 몰리는 Locust 부하 테스트 계획을 구체화했다. 관련 후속 검증은 [GD-232](https://ureca4.atlassian.net/browse/GD-232)와 연결한다.
- 차수마다 시험 시작 30분 뒤 마감하는 별도 이벤트를 준비하고, 20분 점진 증가·2분 급증·8분 최대 부하·마감 후 10분 감소로 구성했다.
- 최대 VU를 1천·5천·1만·2만·3만·5만·10만의 7차로 나눴다. 7차는 6차의 목표 부하·업무 처리·회복·정합성 기준을 충족한 경우에만 시도하도록 했다.
- 실제 RPS, API별·구간별 p50·p95·p99와 오류 유형을 기록하고, 중단 시에도 완료한 차수의 보고서를 남기도록 전달용 프롬프트를 정리했다.

## 고민과 판단

- 실제 자정 초기화 검증은 이번 혼합 시험에서 제외했다. 서버 시간과 초기화 코드를 바꾸지 않고 이벤트 마감 시각을 기준으로 시험한다.
- 이전의 보상 20%·응모 30%·조회 50%는 임의 제안값이므로 고정 조건에서 제외했다. 비교할 차수 사이에는 같은 구간의 요청 구성을 유지한다.
- 목표 VU 도달만으로 성공으로 보지 않는다. 서버 지연과 부하 발생기 자원 부족을 구분하고, 정상 업무 처리와 마감 후 거절도 확인하도록 했다.

## 확인 결과 / 막힌 점

- 계획과 전달용 프롬프트를 작성했으며 실제 부하 테스트·통합테스트·빌드는 실행하지 않았다. 성능이나 정합성 통과 결과는 없다.
- 차수 사이 최소 5분 회복 시간을 포함하면 6차까지 최소 4시간 25분, 조건부 7차까지 최소 5시간 10분이다. 데이터 준비·정합성 점검과 추가 회복 시간은 별도다.
- 실제 실행 전 테스트 데이터, 배포 버전, Locust 워커 자원과 서버·DB 관측 수단 확인이 필요하다.

## 다음 할 일

- 작은 부하에서 신규 업무가 성공하는지 확인한 뒤 단계적으로 실행한다.
- 응모권 이력·보유량, 중복 보상, 마감 판정, 자동 추첨 상태를 대조하고 실제 측정 결과를 별도로 기록한다.
