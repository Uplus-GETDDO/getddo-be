## 고민과 판단

- 이벤트 삭제 API는 존재하며 시작 전·응모 이력 없음 조건을 만족해야 한다. 테스트 데이터 정리는 API 부재로 단정하지 않고 실제 데이터의 삭제 가능 조건을 확인해야 한다.
- INACTIVE 사용자의 로그인·응모·모든 조회가 일괄 거절된다는 공통 계약으로 해석하지 않았다. 검증할 API별 기대값 확인이 필요하다.
- 어뷰징의 EVENT 집계 근거와 실제 이벤트 연결은 구분한다. 현재 코드·스펙은 이벤트 연결 필드의 null을 허용하므로, 해당 표본의 caseId와 요청 이벤트를 확인하기 전 버그로 단정하지 않는다.
- 30초 폴링으로 화면 반영 p95 2초를 검증할 수 없다. API 조회 가능 시각·화면 표시 시각·알림 생성 시각을 구분하고, 제시된 비기능 목표의 원문 근거를 먼저 확인하도록 정리했다.
