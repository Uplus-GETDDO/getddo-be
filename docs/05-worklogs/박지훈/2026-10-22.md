## 오늘 한 일

- [실패한 CI 보고서](https://github.com/Uplus-GETDDO/getddo-be/actions/runs/39700244707)에서 `Clock.instant()`가 `ZoneOffset`을 반환한 `ClassCastException`을 확인했다. 다른 스레드의 시계 조회가 Mockito 응답 설정에 끼어드는 최소 재현에서도 반환 타입 혼선을 확인했다.
- 삭제 테스트의 시계 mock을 초기화 때부터 유효한 테스트 전용 시계로 교체하고, 삭제 재요청의 시간 이동은 `AtomicReference`로 제어했다. 이 테스트에서 불필요한 추첨 재시도 워커는 클래스 단위로 비활성화했다.
- FE 이미지 업로드 요청의 최소 해상도·`target=BANNER`·SVG 허용 여부를 검토했다. 실제 S3 호출 없이 현재 서비스와 저장 대역으로 1×1 PNG 허용, BANNER 미지원, SVG의 `EVENT-018` 거절을 확인했다. 테스트 이미지 4건 정리는 사용자 요청으로 제외했다.
- 배포 프론트의 이벤트 404를 조사했다. 사용자2의 실제 추첨 발표 알림은 `/events/{id}/results`를 제공하지만 FE에는 이 경로가 없어 404 화면이 표시되는 것을 재현했다. 같은 이벤트의 상세 API는 200이고 `/events/{id}` 화면은 새로고침 후에도 정상이다. 발표 알림 링크 생성부(`DrawPublicationNotificationService`)와 FE 라우팅의 불일치이며, 기존 알림 링크도 처리할 수 있는 FE 경로 보완이 필요하다. 알림 읽음 상태·이벤트 데이터·코드는 변경하지 않았다.

## 고민과 판단

- Mockito 응답을 다시 설정하는 순서에 의존하는 대신, 여러 스레드가 읽어도 반환 타입이 변하지 않는 실제 테스트 시계를 사용했다. 기존 동시 삭제·알림 생성 경합과 롤백 검증은 유지한다.
- 최소 해상도와 배너 대상은 추가할 수 있지만 기존 허용 기준을 바꾸는 별도 작업이다. 사용자가 FE에 SVG 거절·JPG/PNG만 허용하는 기존 정책 유지를 전달했다고 확인했다. 이번에는 이미지 코드를 변경하지 않았다.
